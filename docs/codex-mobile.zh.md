# 在手机上让 Codex 操作小红书工具

[English](codex-mobile.en.md)

小红书工具和 Codex 运行在同一台 Mac 上。手机通过办公小镇给 Codex 原会话发要求，Codex 调用本机工具，结果继续回到这个会话。手机不需要直接连接小红书服务。

这是利用现有会话和 HTTP 接口的配置方法。完整的手机到发布流程尚未完成实机验收；手机员工聊天也没有专门的小红书草稿和图片预览页面。

## 准备 Mac

按本项目 README 完成安装和登录，打开一个专门处理小红书内容的 Codex 会话。记录项目的绝对路径、Python 环境和服务地址。

如果使用本机 Web 服务，可在项目根目录、已安装 Web 依赖的环境中运行：

```bash
python -m uvicorn src.web.app:app --host 127.0.0.1 --port 8000
```

只在本机调用时使用回环地址。这个服务的登录接口检查的是小红书账号；不要把它当作对远程调用者的访问认证。

在 Codex 所在的环境检查：

```bash
curl --fail --silent --show-error http://127.0.0.1:8000/healthz
curl --fail --silent --show-error http://127.0.0.1:8000/api/auth/status
```

健康检查成功不代表小红书账号已经登录。未登录或遇到验证码时，在 Mac 上完成登录。Mac 需要保持开机，服务也需要继续运行。

## 给 Codex 的操作说明

把下面的内容发到这个专用会话，替换项目路径和服务地址：

```text
你负责使用本机的小红书 AI 发布助手。
项目路径：<项目的绝对路径>
服务地址：http://127.0.0.1:8000

先检查服务和小红书登录状态。失败时报告具体问题。
由你根据我的要求写文案；保存草稿使用 POST /api/content。
查看草稿使用 GET /api/content/{content_id}，列表使用 GET /api/content。
每次返回草稿 ID、标题、完整正文、标签和图片路径，方便我从手机确认。
修改文案后先保存为一份新草稿，并指出它替代哪一份，等待我确认最新内容。

所有生成、改稿和跟进请求默认只做草稿。
只有我明确指定草稿 ID 并要求发布时，才调用 POST /api/publish，设置 auto_publish=true。
遇到发布超时或不明确的结果，先检查状态和浏览器，不要自动重发。
发布接口接受任务不代表发布完成；继续查询该内容，报告实际状态。
不要把密码、Cookie、验证码或模型密钥发到会话里。
```

现有 `POST /api/content` 接收已写好的文案，不会自己调用模型生成文章。HTTP 服务也没有文案修改接口，所以这份说明用新草稿承接修改。

可供 Codex 使用的草稿请求结构：

```json
{
  "title": "示例标题",
  "content": "这里放已经写好的正文",
  "tags": ["办公小镇"],
  "images": []
}
```

发到 `POST /api/content` 后，从返回的 `data.id` 取得草稿 ID。图片填工具执行环境可访问的路径；在 Docker 内执行时要使用容器路径，不能直接填 Mac 上的路径。真实发布前需按工具的内容校验要求准备图片。

## 从手机继续这个会话

在办公小镇连接这台 Mac，导入上述 Codex 会话。先发：

> 只检查小红书服务能否访问，回复检查结果。不要创建内容或发布。

刷新员工输出，确认回复来自这个会话，再发：

> 帮我写一篇办公小镇的介绍，语气自然一点，先保存草稿。返回草稿 ID 和完整正文，暂时不要发布。

改稿可以继续回复：

> 开头短一点，保留“离开电脑也能继续处理任务”的意思。另存新草稿，发我最新 ID 和正文。

文字和路径可以通过现有会话返回。Mac 本地图片路径不等于手机可打开的图片链接；目前应另行查看图片，确认标题、正文、封面和目标账号后再要求发布。

## 核对结果

`POST /api/publish` 的 `auto_publish=false` 只填写浏览器，仍需要在电脑浏览器中确认；它不是手机发布确认功能。明确授权的自动发布使用 `auto_publish=true`。

发布请求返回后，查询内容状态。当前实现会记录 `publishing`、`published` 或 `failed`；最终是否成功仍要结合工具输出和实际笔记核对。结果不明确时先核查，避免重复发布。

普通管家聊天目前只有任务查询工具。这里的执行者是 Codex；手机持续跟进也是通过向原会话发消息来跟进。初次使用建议手动发要求、手动确认发布，不把发布放进宽泛的自动跟进目标。
